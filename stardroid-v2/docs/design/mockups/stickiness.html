Sky Map v2 · Design exploration

Stickiness: widgets & notifications

Home-screen widgets and rare, high-signal notifications, all computed offline from the shipped catalog and ephemeris. Companion to the events-engine proposal; sequencing is moon widget → tonight widget → shower notifications. Widget mockups use the shipped Deep Space / Star Gold palette (D73).

Quiet by default Every notification channel ships off. Widgets are the default stickiness surface because placing one is itself the opt-in.
Rare and actionable At most one notification per day, and only when there is something to do tonight. A skipped night is a feature.
We do the astronomy Every alert carries the judgment call a calendar can't make: moon interference, altitude, local darkness hours.
One engine, many faces Widgets and notifications are renderers over the same offline events scan — one subsystem to test, not five.

Widgets

Four widgets on a night home screen. All use the app surface color at 86% opacity over the user's wallpaper, 22 dp corner radius, Starlight text, Star Gold reserved for the single most important value in each widget.

A
Moon phase — the anchor widget Phase disc is drawn, not an image asset: correct terminator from LunarPhase, correct orientation for the user's hemisphere. Updates once per day plus on onEnabled; tap opens the app centered on the Moon.
B
Countdown — borrowed anticipation Ring counts down from event announcement (or 30 days). Event auto-advances: after the Perseids peak it rolls to the next shower or moon extreme. The green note line is the "we did the astronomy" hook — shown only when true.
C
Tonight — the flagship Two to three highlights max, ranked by the events engine; each row is individually tappable and deep-links to that object on the map. The third slot may be an honest downgrade ("bright moon") — credibility is the retention mechanism. On a nothing night: "Quiet sky tonight — next event Thu."
D
Rise & set — the customisable one Object chosen in the widget configuration activity at placement (searchable list: planets, Moon, bright stars, Messier). Arc shows tonight's altitude track with "now" in gold. One object per instance; users who want three place three.
+
Shared mechanics All widgets re-render via one daily WorkManager job using the last known coarse location — no GPS wake, no network. Glance (Compose) implementation. Follows system dark/light only in text contrast; the navy surface is the brand and stays.

Notifications

Rendered as standard system notifications — no custom layouts to fight OEM skins. The voice is a knowledgeable friend, not a service: plain sentences, local times, one concrete tip. Each type is its own channel so the system settings screen prunes exactly.

1
Shower peak — the flagship notification Fires the evening of the peak, not at an astronomically-correct-but-useless 3 am. Body always answers: when, which direction, is the moon a problem, what will I see. "Mute showers" opens the channel's system toggle — every alert names its own off-switch.
2
Conjunction — the "what are those two?" moment Sent the evening before for morning events. "Remind me at…" schedules a one-shot follow-up via the events engine, not an exact alarm — inexact windows are fine at these timescales.
3
Tonight digest — collapsed by default User-scheduled time (default: 30 min after sunset). Suppressed entirely when the engine ranks nothing above threshold — silence keeps the signal. Expands to the same three lines as widget C.
!
What never happens No streaks, no "we miss you", no more than one notification per channel per day, no notification that duplicates what a placed widget already shows unless the user opted into both.

1
The contract is the copy "At most once a day. Everything is off until you turn it on." — stated where the user decides, not buried in a help page. Frequency expectations ("about 12 a year") appear per channel.
2
Channels map 1:1 to system channels The in-app toggles and Android's own notification settings can never disagree; the screen reads channel state from NotificationManager. If the user revoked notification permission, every row shows an inline "Allow in system settings" affordance instead of a dead toggle.
3
Rise alerts are per-object opt-in The chip row is the entire mental model: your objects, listed. "Add object" reuses the search UI. This is deliberately not a general alarm clock — one alert per object per night, "rises into good view" (alt > 10°, sun down), not raw rise time.

Permission flow

Android 13+ makes notifications opt-in; the ask has to be earned. Never at first launch.

User flips a toggle The first enabled channel is the trigger. Context is maximal: they just asked for exactly this.
System sheet appears POST_NOTIFICATIONS requested only now. The toggle they flipped stays visually on, pending.
If denied Toggle returns to off with an inline row: "Notifications are blocked for Sky Map — allow in system settings", deep-linking to the app's notification settings. No nagging re-prompt.
Widgets need none of this Another reason they ship first: full stickiness loop with zero permission surface (coarse location is already granted for the map itself).

Discovery

Nobody finds widgets in the launcher's long-press picker, and the notification sheet can't be the channel — those ship later and default to off. Discovery is in-app, at moments of demonstrated interest, using the system pin dialog (requestPinAppWidget) so placement is one tap instead of a home-screen safari.

A
Contextual promo — the primary path Shown at the bottom of an info card only when the object has a matching widget (Moon → moon widget, planet → rise & set pre-configured to that planet). Someone reading the Moon's card has already voted with their attention. Dismissed once for an object type → never shown for it again.
B
One tap, pre-configured The pin dialog carries the configuration, so a rise & set widget offered from Saturn's card lands already set to Saturn — no config screen. On the few launchers that don't support pinning, the button falls back to a short instruction sheet.
+
The supporting cast Settings → Widgets gallery row (the findable-on-purpose path); one dismissible what's-new card when the feature first ships — shown once, never repeated; proper Glance previewLayout previews and a Play-listing screenshot for people who do browse the picker.
!
Ruled out No widget pitch during first-run onboarding, no repeated nags, no discovery via notifications. The reverse path is the one that works: a placed Tonight widget deep-links into the map, which may quietly point at Settings → Notifications → Meteor showers — widgets recruit for notifications, not the other way round.

Open questions for the decision log

  • Material You dynamic color on widgets: brand navy always, or offer a "follow wallpaper" style? Mockups assume brand-always; a translucency slider may be the cheaper personalization.
  • Does the tonight digest merge into the shower channel on peak nights, or does the shower alert replace the digest? Proposal: shower alert wins, digest suppressed — enforces the one-per-day contract.
  • Threshold for "worth a look tonight": what score suppresses the digest? Needs the events-engine quality metric defined first.
  • Night mode: should widgets red-shift after the user's chosen night-mode hours? Tempting, but home screens are day surfaces; lean no for v1.
  • Do rise alerts belong in v1 of the settings screen even if greyed "coming soon"? Lean no — ship rows only for channels that work.
